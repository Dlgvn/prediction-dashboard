Wire the CSV parsing core into `DashboardState`: an `rx.upload`-compatible async upload
handler that parses and stages a preview (writing nothing), an explicit `confirm_import`

Add `async def handle_csv_upload(self, files: list[rx.UploadFile])`, decorated `@rx.event`:
  - Reset all import fields and `_staged_import_rows` first, then set
    `self.import_stage = "idle"` guard state.
  - If `files` is empty, return with no state change.
  - Take only the first file (`rx.upload` is configured `max_files=1` in plan 10-03). Set
    `self.import_filename` from the file's name attribute (prefer `.name`, fall back to
    `.filename`) for the "Parsing {filename}…" copy.
  - `contents = await file.read()`.
  - Call `parse_import_csv(contents, SERIES_ATTRS, [r.date for r in self.rows])`.
  - If `not result.ok`: set `self.import_error = result.error`, `self.import_stage = "error"`,
    leave `_staged_import_rows` empty, and return. Do NOT touch `edit_error`.
  - Otherwise store `result.rows` into `_staged_import_rows`, copy the three counts onto the
    corresponding fields, and set `self.import_stage = "preview"`. NO database session is
    opened anywhere in this handler — IMPORT-01 requires the preview to precede every write.
  - Wrap the read/parse call in try/except Exception and fall back to the error stage with
    the parser's UNPARSEABLE_ERROR-equivalent message rather than letting an exception escape
    into Reflex's event loop.

Add `def confirm_import(self) -> None`:
  - Return early if `self.import_stage != "preview"`.
  - Capture `before = len(self.rows)`.
  - Open exactly one `with rx.session() as session:` block, loop `for record in
    self._staged_import_rows:` doing `session.add(PriceRow(**record))`, then a single
    `session.commit()` after the loop — one batch write, mirroring `_commit_draft_cell`'s
    session usage. Do NOT query-then-update any existing row and do NOT use a merge/upsert:
    the parser has already excluded every duplicate date, so this path can only ever INSERT.
    Any `session.merge`, `setattr` on a fetched row, or `PriceRow.select()` lookup here would
    be an IMPORT-02 violation.
  - Clear `self._staged_import_rows = []` so a repeated confirm cannot double-write.
  - Call `self.load_rows()` — mandatory, this is what makes the new rows visible to Phase 7's
    `visible_rows`, Phase 8's `summary_cards`, and Phase 9's `_export_bytes`, all of which
    read `self.rows`.
  - Set `self.import_added_count = len(self.rows) - before` so the "Import complete: {N} rows
    added." copy reflects the post-`load_rows` reality rather than the stale parse-time count
    (10-UI-SPEC.md Interaction Contract makes this explicit).
  - Set `self.import_stage = "done"`.

Add `def cancel_import(self) -> None` and `def dismiss_import(self) -> None`:
  - Both reset every import field to its default and clear `_staged_import_rows`; neither
    opens a session. `dismiss_import` backs the "Done" text-button on the completed panel;
    `cancel_import` backs "Cancel" on the preview panel. Implement `dismiss_import` by
    delegating to `cancel_import` (or a shared `_reset_import` private helper) so the reset
    logic exists once.

Do not modify `load_rows`, `_commit_draft_cell`, `commit_edit`, `visible_rows`,
`summary_cards`, or `_export_bytes` — this plan is purely additive to state.py.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser upload -> `handle_csv_upload` | Untrusted file bytes and filename cross into the backend |
| `_staged_import_rows` -> SQLite | Only parser-approved rows cross; this is the sole write point for the feature |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05 | Tampering | `confirm_import` | mitigate | Insert-only batch write; no `session.merge`, no fetch-then-`setattr`, no upsert. Grep-enforced in acceptance criteria, so an existing row cannot be mutated by import (IMPORT-02). |
| T-10-06 | Elevation of Privilege | DB access boundary | mitigate | All `rx.session()` calls stay in `state.py`; `csv_import.py` and `app.py` contain none. Verified by `grep -rn "rx.session" app/app/ \| grep -v state.py` returning empty. |
| T-10-07 | Denial of Service | reactive state size | mitigate | Parsed rows live in the backend-only `_staged_import_rows` var (leading underscore), never serialized to the frontend; row/size caps enforced in `parse_import_csv`. |
| T-10-08 | Repudiation | Import result reporting | mitigate | `import_added_count` is recomputed from `len(self.rows)` growth after `load_rows()`, so the user-facing count cannot report rows that were not actually persisted. |
| T-10-09 | Information Disclosure | `import_filename` echoed into UI copy | accept | Filename is user-supplied and shown only back to that same single local user; Reflex escapes text nodes, and no path is reconstructed from it. |
| T-10-SC | Tampering | package installs | accept | No new packages; `requirements.txt` unchanged (10-UI-SPEC.md Registry Safety). |
</threat_model>
