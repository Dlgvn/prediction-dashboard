## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser file picker / drag-drop -> `rx.upload` | Untrusted file selection crosses into the backend handler |
| render layer -> state | Components may only read `DashboardState` vars and dispatch its handlers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-10 | Elevation of Privilege | `app.py` render layer | mitigate | `csv_import_control` reads state vars and dispatches state handlers only; `grep -rn "rx.session" app/app/app.py` must return nothing, asserted by `test_app_py_has_no_session_calls`. |
| T-10-11 | Denial of Service | `rx.upload` props | mitigate | `max_files=1`, `multiple=False`, and `accept={"text/csv": [".csv"]}` narrow the client-side surface; the authoritative size/row caps remain server-side in `parse_import_csv` (client hints are never trusted alone). |
| T-10-12 | Tampering | Confirm affordance | mitigate | Confirm is a distinct explicit click bound to `confirm_import`; the upload handler itself performs no write, so no file drop can auto-commit (IMPORT-01). |
| T-10-13 | Information Disclosure | error text rendered in the UI | accept | Only fixed module-constant messages from `csv_import.py` are surfaced; no exception text or filesystem path is rendered. |
| T-10-SC | Tampering | package installs | accept | No new packages, no `requirements.txt` change; `rx.upload`/`rx.upload_files` ship with the already-pinned `reflex==0.9.8.post1` (10-UI-SPEC.md Registry Safety). |
</threat_model>
