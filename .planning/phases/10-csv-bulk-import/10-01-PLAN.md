  <behavior>
    - Header exactly `date` + the 16 series_attrs in that order -> parsing proceeds.
    - Header with a missing column, an extra column, or a different order -> ok=False, error=HEADER_MISMATCH_ERROR, and `rows` is empty (no row-level parsing attempted at all).
    - Bytes that pandas cannot read as CSV (e.g. b"\x00\x01\x02not,a;csv") -> ok=False, error=UNPARSEABLE_ERROR, `rows` empty.
    - Empty file / header-only file -> ok=True, rows empty, all counts 0.
    - Row whose date duplicates an entry in `existing_dates` (same YYYY-MM) -> duplicate_count += 1, row excluded from `rows`.
    - Two rows inside the same file sharing a month -> first accepted, second counted as duplicate (in-file dates accumulate into the duplicate check).
    - Row with a non-numeric cell ("abc") or a negative cell ("-5") -> invalid_count += 1, row excluded.
    - Row with an unparseable date ("not-a-date", "2026-13-01") -> invalid_count += 1, row excluded.
    - Row with blank cells -> accepted, those columns land as None.
    - Valid new row -> appears in `rows` as {"date": iso, **{attr: float|None}} covering all 16 attrs, and added_count == len(rows).
    - File larger than MAX_UPLOAD_BYTES -> ok=False, error=FILE_TOO_LARGE_ERROR before parsing.
    - Data row count above MAX_IMPORT_ROWS -> ok=False, error=TOO_MANY_ROWS_ERROR, rows empty.
  </behavior>

Define `ImportParseResult` as a `@dataclasses.dataclass(frozen=True)` with fields:
  ok: bool, error: str, rows: list[dict], added_count: int,
  duplicate_count: int, invalid_count: int
Add a `total_skipped` property returning duplicate_count + invalid_count.

Define the single public function:
  `def parse_import_csv(raw: bytes, series_attrs: tuple[str, ...], existing_dates: list[str]) -> ImportParseResult`

Order of operations, strictly (D-06 fail-fast is load-bearing — any row-level work before
the header gate is a defect):
  1. Size gate: `len(raw) > MAX_UPLOAD_BYTES` -> return failure with FILE_TOO_LARGE_ERROR.
  2. Parse: `pd.read_csv(io.BytesIO(raw), dtype=str, keep_default_na=False)` inside a
     try/except catching `Exception` -> on failure return failure with UNPARSEABLE_ERROR.
     `dtype=str` + `keep_default_na=False` is required so every cell reaches
     `validate_numeric` as the raw string the manual-edit path would have received, and so
     blanks arrive as "" rather than float NaN.
  3. Header gate: compare `tuple(frame.columns)` against `("date", *series_attrs)`. On any
     mismatch return failure with HEADER_MISMATCH_ERROR and an empty `rows` list — return
     immediately, before any iteration over frame rows.
  4. Row-count gate: `len(frame) > MAX_IMPORT_ROWS` -> return failure with TOO_MANY_ROWS_ERROR.
  5. Row loop: maintain `seen_dates = list(existing_dates)`. For each record:
       - call `validate_date(str(record["date"]), seen_dates, own_original_date=None)`;
         on failure, increment duplicate_count when the returned error is
         DATE_DUPLICATE_ERROR (that is the IMPORT-02 skip reason per D-03), otherwise
         increment invalid_count; `continue`.
       - for each attr in series_attrs call `validate_numeric(str(record[attr]))`; on the
         first failure increment invalid_count and `continue` to the next record (a row is
         all-or-nothing — never write a partially-validated row).
       - on full success append `{"date": iso_date, **values}` to rows and append `iso_date`
         to `seen_dates` so a later row in the same file duplicating that month is caught.
  6. Return `ImportParseResult(ok=True, error="", rows=rows, added_count=len(rows), ...)`.

Every numeric and date decision must be delegated to the imported validators. Do not write
`float(...)`, `< 0`, `date.fromisoformat`, or any regex date/number check in this module.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded file bytes -> parser | Fully untrusted binary content supplied by the user's browser; may be non-CSV, oversized, or contain hostile cell values |
| parser output -> DB write (plan 10-02) | Only rows that cleared both the header gate and per-row validation may cross |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `parse_import_csv` row loop | mitigate | Every cell goes through `validate_numeric`; every date through `validate_date`. No `float()` or manual date parsing in this module (grep-enforced in acceptance criteria). |
| T-10-02 | Denial of Service | `pd.read_csv` on uploaded bytes | mitigate | `MAX_UPLOAD_BYTES` checked before parsing and `MAX_IMPORT_ROWS` checked after header validation; both return a clean error rather than parsing on. |
| T-10-03 | Tampering | Duplicate-date handling (IMPORT-02) | mitigate | `validate_date` with an accumulating `seen_dates` list is the sole duplicate authority; duplicate rows are excluded from `rows`, so the write path in 10-02 physically cannot receive them. |
| T-10-04 | Information Disclosure | Error messages returned to the UI | accept | Errors are fixed module constants, never interpolated exception text or file paths — no internal detail leaks. |
| T-10-SC | Tampering | package installs | accept | No new packages. `pandas` and `reflex` are already pinned; `requirements.txt` is unchanged by this phase (10-UI-SPEC.md Registry Safety). |
</threat_model>
