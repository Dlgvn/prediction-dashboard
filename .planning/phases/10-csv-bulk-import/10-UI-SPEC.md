# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase adds one substantial new UI surface** — an upload control, a
summary-style result panel, and confirm/cancel controls in the Data Entry
section. It introduces **zero new design tokens**. Every value below is
inherited verbatim from `06-UI-SPEC.md` / `app/app/theme.py` (Phase 6's
locked light design system) and follows `07-UI-SPEC.md`'s precedent for how
an additive control cites the base contract. Where a row says "reuse," that
means: import the existing constant from `theme.py`, do not hardcode a new
literal.

## Color

Reuse `app/app/theme.py` exactly — no new hex values.

| Role | Value | Usage in this phase |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` (`PAGE_BG`) | Unchanged page background |
| Secondary (30%) | `#FFFFFF` (`SURFACE`) with `CARD_BORDER` | Dropzone surface (idle state) and the import-summary panel both sit on this existing card surface — no new surface color introduced |
| Accent (10%) | `#2563EB` (`ACCENT`) | Reserved for: the dropzone's active/hover/dragging border+icon color, and the **Confirm import** primary button (`color_scheme="blue"`, same treatment as "Add row"/"Export to Excel"). Do not use accent for the summary panel's count text or borders. |
| Destructive | `#DC2626` (`DESTRUCTIVE`) | Reserved for: the malformed-file error banner text/icon (D-06), and the "skipped (invalid value)" and "skipped (duplicate date)" count numbers in the summary panel — these are informational counts, not confirm actions, but use the destructive-adjacent red to visually flag "did not import" (consistent with the existing `export_failed` red-text pattern at app.py:302, which reuses `DESTRUCTIVE` for a non-button informational message). |

Accent reserved for (updated list, Phase 10 addition in bold): fan chart base
line/band, horizon slider, primary buttons (Export to Excel, Add row),
active Series select state, "show all history" switch checked state,
**and the Import CSV dropzone active/hover state + Confirm import button**.
Never used for card borders, headings, or table chrome.

**Cancel button** uses the neutral/gray treatment (`color_scheme="gray"`,
variant `"soft"` or `"outline"` — matching Radix's standard secondary-button
pattern, no new token), NOT the destructive red — cancel is a neutral
"discard preview, no data written" action, not a delete.

**Confirm import button is NOT destructive-styled.** It uses the same
`color_scheme="blue"` / accent treatment as "Add row" and "Export to Excel"
(primary, non-destructive CTA family), per the brief: confirm reads as a
primary action, not a delete-style confirm. This is a deliberate departure
from the two-click "Confirm delete?" red-button precedent — that precedent
exists because delete is irreversible data loss; import-confirm only ever
*adds* new, previously-absent rows and never overwrites, so it does not
carry the same risk profile and should not borrow delete's red urgency.

No second semantic color needed beyond the existing `DESTRUCTIVE`/`UP`/`DOWN` pair.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section control label | "Import CSV" — button/dropzone trigger label, placed directly beside "Add row" in `data_entry_section()` per D-05 |
| Dropzone idle state | "Drag and drop a CSV file here, or click to browse." (14px body, `MUTED_TEXT`, centered, with the `"upload"` icon above it in `ACCENT` when hovered/dragging, `MUTED_TEXT` when idle) |
| Dropzone uploading state | "Parsing {filename}…" — shown in place of the idle instruction text while the backend handler reads/parses the file; no progress bar needed (files are small per the size cap, parse is near-instant) |
| Dropzone error state (D-06 malformed file) | Heading-less inline banner: "This file doesn't match the expected format. Expected columns: date, HDAN, PPAN, … (16 series columns), in that order — export a template from 'Export to Excel' if unsure." — red icon (`"circle-alert"`, `DESTRUCTIVE`) + `DESTRUCTIVE`-colored 14px body text, rendered where the dropzone was; a "Try again" text-button (accent, no icon) clears the error and returns to idle state |
| Preview/summary heading | "Import preview" (14px body, `font_weight=FONT_WEIGHT_SEMIBOLD` — a sub-label, not a full `RADIX_SIZE_HEADING`, since it lives inside the Data Entry section which already has its own "Data Entry" `h2`) |
| Summary count — added | "{N} rows will be added" — default/neutral text color (not `UP`/green; this is a plain count, not a directional indicator per D-11's arrow convention which is reserved for price direction, not import counts) |
| Summary count — skipped, duplicate | "{M} rows skipped (duplicate date)" — `DESTRUCTIVE` color per the Color section above |
| Summary count — skipped, invalid | "{K} rows skipped (invalid value)" — `DESTRUCTIVE` color per the Color section above |
| Summary count — all skipped, zero added (edge case) | Same three-line summary still renders (0 rows will be added), no separate empty-state copy — the Confirm button is disabled in this case (see Interaction Contract) rather than hidden, so the user always sees why nothing happened |
| Confirm CTA | "Confirm import" — primary, accent-styled, per Color section (NOT destructive-styled) |
| Cancel CTA | "Cancel" — neutral/gray, discards the preview and returns to the dropzone idle state, no confirmation step needed (cancel is always safe — nothing has been written yet) |
| Post-import result (after Confirm is clicked and the batch write completes) | "Import complete: {N} rows added." — reuses the same summary panel, now with Confirm/Cancel replaced by a single "Done" text-button (or the panel auto-dismisses after acknowledgment; Claude's Discretion on exact dismiss mechanic) that returns to the idle dropzone |
| Primary CTA (Data Entry section, existing) | "Add row" (unchanged) |
| Empty state | Reuse existing `empty_state()` verbatim — unaffected by this phase |
| Destructive confirmation (existing, unchanged) | Delete row: "Confirm delete?" — NOT reused for import; import has no destructive path (D-03: existing data is never overwritten) |

## Interaction Contract (new — specific to this phase)

This section exists because the primary new surface in this phase is
interactive/stateful (upload → parse → preview → confirm/cancel), not purely
visual — replaces the template's generic layout section for this phase.

- **Control:** `rx.upload` wrapping a dropzone-styled `rx.box` (icon +
  instruction text), paired with a small "Import CSV" trigger — per
  Reflex/STACK.md convention, `rx.upload` itself provides both the
  click-to-browse and drag-and-drop affordances; no separate button is
  needed to open a file picker (do not add a redundant second control).
- **Placement:** Inside `data_entry_section()`, in the same `rx.hstack` row
  as `add_row_button()` per D-05 — `[Add row] [Import CSV]`, `spacing="2"`,
  both `size="2"`. The dropzone itself (once a file is selected/dragged)
  expands below this row, not inline in the button row, so it doesn't
  distort button layout while idle.
- **Three visual states for the dropzone**, all sharing the existing
  `CARD_BORDER`/`CARD_RADIUS`/`SURFACE` chrome:
  1. **Idle** — dashed `CARD_BORDER` (border_style="dashed", matching the
     existing "no data yet" freshness-chip dashed-border precedent at
     app.py:272), `MUTED_TEXT` icon+copy.
  2. **Uploading/parsing** — same dashed border, `ACCENT` icon, "Parsing
     {filename}…" text; no spinner component needed unless parse exceeds a
     perceptible delay — Claude's Discretion whether to add `rx.spinner`
     size="1" next to the text if implementation reveals parse isn't
     instant for max-size files.
  3. **Error** — solid `DESTRUCTIVE`-tinted border (or keep `CARD_BORDER`
     solid + red icon/text only — Claude's Discretion, but text/icon color
     MUST be `DESTRUCTIVE`), per D-06 copy above.
- **Preview/summary panel:** appears as its own `rx.box` (same
  `SURFACE`/`CARD_BORDER`/`CARD_RADIUS`/`CARD_PADDING` card treatment used
  throughout the app) directly below the dropzone once parsing succeeds —
  NOT a modal, NOT a full row-grid (D-04). Three count lines + Confirm/Cancel
  button row, `spacing="2"` vertical stack.
- **Confirm button disabled state:** `disabled` when the "will be added"
  count is 0 (nothing to commit) — mirrors the existing `add_row_button`'s
  `disabled=~DashboardState.can_add_row` pattern; do not hide the button,
  disable it, so the summary counts remain visible as the explanation.
- **Wiring pattern:** follows the two-click delete-confirm precedent's
  *spirit* (explicit confirm step, no silent auto-commit) without copying
  its exact mechanic — this is parse-then-preview-then-explicit-confirm,
  a three-state flow (idle → preview → done), not a two-click arm/confirm
  on a single control.
- **Batch write on Confirm:** goes through `DashboardState`'s existing
  `rx.session()` boundary only (no new session call site), then calls
  `load_rows()` to refresh `self.rows` so the newly-imported rows
  immediately appear in `visible_rows` (Phase 7 windowing),
  `summary_cards` (Phase 8), and export (Phase 9) — this is a state-layer
  concern, but the UI-SPEC records it because the "Import complete: {N}
  rows added" copy above must reflect the same `self.rows`-derived count,
  never a stale parse-time count.
- **Cancel:** clears the preview/parse-result state and returns the
  dropzone to idle — no write occurs, no confirmation step (cancel is
  always non-destructive since nothing was written yet).
- **No loading skeleton for the summary panel** — parse-then-count is
  synchronous relative to the small file-size cap; only the dropzone's own
  "Parsing…" text communicates in-flight state.
