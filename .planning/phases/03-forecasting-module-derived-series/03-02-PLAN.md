<planner_correction>
## 03-RESEARCH.md Pattern 1 has a lag-alignment error — do not copy it verbatim

Pattern 1 says the future exog frame "simply uses `_forecast_predictor`'s forward path
directly, not shifted again." That is correct ONLY for lag-1 predictors and WRONG for
`ammonia`, whose lag is 3.

The verified fit convention, read from `backend_research/run_arima_sarimax_wf.py`
`build_sarimax_records` (lines 228-237): the exog value the model sees at time `t` for
predictor `p` is `history[p].shift(lag_p)`, i.e. the predictor's own value at `t - lag_p`.

Therefore at future step `h` (1-indexed), the exog value the model needs for predictor `p`
is that predictor's value at time `T + h - lag_p`, where `T` is the index of the last
observed row.

- For `lag_p == 1`: step h=1 needs the LAST OBSERVED actual; steps h>=2 need forecast
  step `h - 1`.
- For `ammonia` (`lag == 3`): steps h=1,2,3 need OBSERVED actuals at T, T-1, T-2
  respectively; steps h>=4 need forecast step `h - 3`.

Using the forward path directly for `ammonia` would shift its contribution three months
early — a silent numerical error that produces no exception. Task 1 below specifies the
correct construction and Task 2 asserts it.

Also note: `_forecast_predictor` only needs `horizon - lag_p` steps for a lag-`p`
predictor, but forecasting the full `horizon` steps and indexing into a concatenated
[observed tail || forecast path] array is simpler and equivalent. Prefer the concatenated
array approach.
</planner_correction>
