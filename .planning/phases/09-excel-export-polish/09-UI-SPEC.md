# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note (read first)

**This phase has zero in-app UI changes.** Per `09-CONTEXT.md`, the export button
(`export_button()` in `app/app/app.py`) is unchanged — same label, same icon, same
placement, same click behavior, same styling. EXPORT-02 only enriches the *contents*
of the downloaded `.xlsx` file (`_export_bytes` in `app/app/state.py`) by adding a
second sheet. There is no web-page visual surface for this phase to specify.

This phase therefore **inherits 100% of the Phase 6 design system** (`06-UI-SPEC.md`)
by reference, with no additions, exceptions, or overrides. All tables below restate
the Phase 6 contract for completeness so downstream consumers (planner, executor,
checker) have a single self-contained file, but no phase-9-specific decisions were
made in the Design System / Spacing / Typography / Color sections.

The **only genuinely new user-visible copy this phase introduces** lives inside the
exported Excel file, not the web page: the two sheet names and the Forecast sheet's
column headers. See the Copywriting Contract below — that is the actual design
surface for this phase.

## Copywriting Contract

This is the actual design surface for Phase 9: the exported `.xlsx` file's
user-visible text (sheet tab names and Forecast-sheet column headers). These are
"copywriting" in the same sense as on-screen labels — the user reads them directly
after opening the downloaded file in Excel.

| Element | Copy |
|---------|------|
| Actuals sheet tab name | `"Actuals"` (renamed from openpyxl's default `"Sheet1"`) — D-03, locked |
| Forecast sheet tab name | `"Forecast"` — D-03, locked |
| Forecast sheet column headers | Reuse `FORECAST_TABLE_COLUMNS` labels verbatim (e.g. `"HDAN base"`, `"HDAN bull"`, `"HDAN bear"`, and equivalents for PPAN, Diesel-USD, Diesel-MNT, FX) — same wording as the on-screen forecast table, per Claude's Discretion note in `09-CONTEXT.md`. Do not introduce new header wording. |
| Forecast sheet empty-state | When `forecast_table_rows` is empty (insufficient history), write a header-only sheet with no data rows — mirrors the on-screen `forecast_error` text behavior, no additional copy needed since there is no on-screen-equivalent message inside an Excel file |
| Primary CTA (export button) | Unchanged — no new label; not in scope for this phase |
| Destructive confirmation | Not applicable — this phase adds no destructive action |

No new empty-state heading/body or error-state copy applies to the web page itself;
`export_to_excel`'s existing try/except error handling and its existing user-facing
messaging (if any) are unchanged by this phase.
