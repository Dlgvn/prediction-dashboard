## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-process state -> downloaded .xlsx | Locally-entered numeric data leaves the app as a file the user opens in Excel |
| user browser -> `export_to_excel` event | Single-user local app; the only untrusted-ish input is data the same user typed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `_export_bytes` writing to disk | mitigate | BytesIO-only sink enforced by acceptance criterion in Task 1; no `open(`/path argument permitted |
| T-09-02 | Information disclosure | Forecast sheet contents | accept | Same single local user already sees these values on screen; export adds no new data class and no network egress |
| T-09-03 | Denial of service | Export at large horizon | accept | Horizon is capped at 12 months x 15 columns; the actuals sheet at 167 rows already dominates and is unchanged |
| T-09-SC | Tampering | npm/pip installs | mitigate | Not applicable — no new dependency; openpyxl and pandas are already pinned project dependencies (STACK.md) |
