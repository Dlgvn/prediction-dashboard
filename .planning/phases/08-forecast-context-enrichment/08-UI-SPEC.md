# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase adds exactly TWO new lines to an existing component** — `_summary_card()`
in `app.py` — showing all-time high/low and year-over-year (YoY) % change per series.
It introduces zero new design tokens, zero new colors, zero new typography scale steps,
zero new spacing values, and zero new components. Every value below is inherited
verbatim from `06-UI-SPEC.md` / `app/app/theme.py` (Phase 6's locked light design
system), following the same "reuse, don't hardcode" discipline established in
`07-UI-SPEC.md`.

## Color

Reuse `app/app/theme.py` exactly — no new hex values.

| Role | Value | Usage in this phase |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` (`PAGE_BG`) | Unchanged page background |
| Secondary (30%) | `#FFFFFF` (`SURFACE`) with `CARD_BORDER` | Unchanged card surface — the two new lines render inside the existing summary card box, not a new surface |
| Accent (10%) | `#2563EB` (`ACCENT`) | NOT used by this phase. High/low and YoY are neutral informational text, not an interactive/selected control — do not accent-color either new line. |
| Destructive | `#DC2626` (`DESTRUCTIVE`) | NOT used by this phase. YoY change is not a destructive action; even a negative YoY % is informational, not an error — do not use `DESTRUCTIVE`/red for a negative YoY value. |

Direction pairing reuse (existing `UP`/`DOWN` tokens, D-05 below):
- YoY value text color follows the SAME `UP`/`DOWN`/`MUTED_TEXT` cond pattern already
  used for the existing "vs. latest actual" direction line (`card["direction"]` →
  `UP` `#15803D` / `DOWN` `#DC2626` / `MUTED_TEXT` `#71717A` for flat), reusing the
  same three-way `rx.cond` structure — not a new color decision, an application of the
  existing one to a second metric.
- High/low value text stays `MUTED_TEXT`-adjacent body color (default text color, same
  as `card["range_text"]`) — it has no directional sign, so it never uses `UP`/`DOWN`.

Accent reserved for (unchanged from Phase 6/7): fan chart base line/band, horizon
slider, primary buttons (Export to Excel, Add row), active Series select state, the
"show all history" `rx.switch` checked state. This phase adds nothing to that list.

## Copywriting Contract

| Element | Copy |
|---------|------|
| All-time high/low label (new) | "All-time high/low:" — deliberately distinct from "Expected range:" (D-13, Phase 6) since this is historical data, not the forecast bull/bear band; combined single line per D-04 discretion resolution below |
| All-time high/low value format (new) | "{high formatted 1,234.56} / {low formatted 1,234.56}" — single line, slash-separated, reusing `NUMBER_FORMAT` (`,.2f`) already applied to `card["base"]`/`card["range_text"]`; e.g. "All-time high/low: 512.40 / 298.10" |
| YoY label (new) | "YoY:" — short, matches the terse existing label style ("Expected range:" is the longest existing label; "YoY:" stays well within that width budget) |
| YoY value format (new, computable case) | "{arrow} {abs(pct)}% vs. {month} {year-1}" e.g. "↑ 4.2% vs. Jul 2025" — reuses `ARROW_UP`/`ARROW_DOWN`/`ARROW_FLAT` glyphs from theme.py (direction never conveyed by color alone, per Phase 6 D-11) and the same "vs. X" caption grammar already used for "vs. latest actual" |

| No-data card state | Unchanged — "Add pricing data to see a forecast" (existing `card["no_data_text"]`, Phase 6). When a card has no forecast data at all, the two new lines are not rendered either (they live inside the same `has_data == "yes"` `rx.cond` branch as the existing range/direction lines — see Interaction Contract) |
| Primary CTA | "Export to Excel" / "Add row" (existing, unchanged — this phase touches no buttons) |
| Destructive confirmation | "Confirm delete?" (existing, unchanged — this phase has no destructive action) |

## Interaction Contract (additive-only — no new interactive control)

This section exists because the two new lines are read-only computed text, not a new
control, so most of the template's Layout/Registry sections are not applicable. This
replaces the generic layout section for this phase.

- **Placement:** Two new `rx.hstack` rows appended to the existing `rx.fragment` inside
  `_summary_card()`'s `has_data == "yes"` branch, directly below the existing "vs.
  latest actual" `rx.hstack` (app.py line ~424-437) and above the closing of the
  `rx.vstack`. Card order becomes: label → base number → "Expected range" →
  "vs. latest actual" direction → **NEW "All-time high/low"** → **NEW "YoY"**. This
  matches 08-CONTEXT.md D-04 exactly.
- **Data source:** Both new lines read two new keys added to the SAME per-card dict
  already produced by `DashboardState.summary_cards` (`@rx.var`) — e.g.
  `card["hilo_text"]` and `card["yoy_text"]` (plus `card["yoy_direction"]` reusing the
  existing three-way direction cond, and `card["yoy_arrow"]` reusing the existing
  `ARROW_UP`/`ARROW_DOWN`/`ARROW_FLAT` glyph pattern). One card = one dict = one
  `rx.foreach` item, unchanged shape discipline from Phase 6.
- **Conditional rendering:** No new `rx.cond` branch is needed beyond the existing
  `has_data == "yes"` / `"no"` split — if a card has forecast data, it necessarily has
  historical actuals (forecast requires history), so high/low is always computable
  when `has_data == "yes"`. YoY specifically can independently be `""` per D-03 even
  when `has_data == "yes"`; when `yoy_text` is `""`, the YoY `rx.hstack` still renders
  its label but the value text is empty — do NOT hide the whole YoY row (avoids layout
  jump between cards that do/don't have a 12-month-back comparator), consistent with
  how the existing flat-direction case already renders an empty `delta_text` in place
  rather than collapsing the row.
- **No loading state needed:** both values are synchronous derived reads from
  `self.rows` inside the existing `@rx.var` — no spinner/skeleton, consistent with
  Phase 7's precedent for synchronous in-memory computation.
- **No new empty/error component** — the existing `card["no_data_text"]` no-data branch
  already covers the "nothing to show" case at the card level; no separate empty state
  is designed for "high/low only" or "YoY only" partial-data scenarios beyond the D-03
  empty-string rule above.
- **`aria_label` update:** the card's existing `aria_label` (app.py line ~450,
  currently `card["label"] + " " + card["base"] + " " + card["delta_text"]`) SHOULD be
  extended to include the new high/low and YoY text so screen-reader users get the
  full card content in one pass — e.g. append `+ " " + card["hilo_text"] + " " +
  card["yoy_text"]`. This is a one-line change to the existing `aria_label` expression,
  not a new accessibility surface.
