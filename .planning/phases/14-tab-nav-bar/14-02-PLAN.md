<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → DashboardState | Tab `on_change` delivers a client-controlled string into `set_active_section` |
| DashboardState → rendered DOM | `active_section` selects which section subtree is rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Tampering | `nav_bar()` `on_change` wiring | accept | An out-of-range `active_section` value matches no render branch, yielding an empty panel. No SQL, filesystem path, or script is derived from it (`rx.tabs.trigger` values are literals in source). |
| T-14-04 | Information Disclosure | conditional section rendering | accept | All three panels show the same single local user's own data; hiding a panel is a layout concern, not an authorization boundary. This app is explicitly single-local-user (PROJECT.md) with no auth surface. |
| T-14-05 | Denial of Service | rapid tab toggling | mitigate | Task 1 forbids attaching any data-loading handler to a tab trigger; `test_index_declares_on_mount_exactly_once` enforces that tab switching cannot amplify into repeated DB reads. |
| T-14-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages — `rx.tabs.*` ships in the installed `reflex==0.9.8.post1`. No install task exists in this plan, so no `[ASSUMED]`/`[SUS]` legitimacy checkpoint is triggered. |
</threat_model>
