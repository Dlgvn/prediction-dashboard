## Color

Zero new color tokens. The tab bar reuses `theme.py`'s existing mode-resolved tokens exclusively, consistent with CONTEXT.md's "no new visual references... calm and understated" direction and the phase's explicit "confirm zero new tokens needed" instruction.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `tokens(mode)["PAGE_BG"]` | Page background (unchanged) — tab bar sits directly on page background, no separate bar background/card treatment (keeps it visually light, not a heavy SaaS pill-nav) |
| Secondary (30%) | `tokens(mode)["SURFACE"]` + `tokens(mode)["BORDER"]` | Tab bar's bottom border only (a single 1px `BORDER`-colored rule beneath the full tab list, standard Radix Tabs underline-style default) — no card wrapper, no background fill on the bar itself |
| Accent (10%) | `tokens(mode)["ACCENT"]` | Reserved strictly for: (1) the active tab's bottom-border indicator (2px `ACCENT` underline under the selected trigger, Radix Tabs' default active-indicator treatment), (2) active tab label text color. Do NOT apply accent to inactive tabs, the tab bar's own background, or the outer 1px separator border. This is the same reservation list Phase 6 already established (accent = fan chart line/band, horizon slider, primary buttons, active Series select) — the active tab indicator is a direct, consistent extension of "accent marks the one selected/active thing," not a new accent use-case. |
| Destructive | `tokens(mode)["DESTRUCTIVE"]` | Not used by the tab bar — no destructive action lives in tab navigation. |

Tab label text color:
- **Active tab:** `tokens(mode)["ACCENT"]` text + weight 600 (semibold) + 2px `ACCENT` bottom-border indicator.
- **Inactive tab:** `tokens(mode)["MUTED_TEXT"]` text + weight 400 (regular) + no border indicator (transparent 2px placeholder to prevent layout shift on selection change).

Accent reserved for (updated list, phase 14 addition in italics): fan chart base line/band, horizon slider active track/thumb, primary CTA buttons (Export to Excel, Add row), active Series select state, *active tab indicator + active tab label*. Never used for the tab bar's own background, inactive tabs, or the outer separator border.

## Tab Bar — Structure & Placement

| Property | Value |
|----------|-------|
| Component | `rx.tabs.root(rx.tabs.list(rx.tabs.trigger("Summary", value="summary"), rx.tabs.trigger("Forecast", value="forecast"), rx.tabs.trigger("Data Entry", value="data_entry")), value=DashboardState.active_section, on_change=DashboardState.set_active_section)` — controlled `rx.tabs.root`, not a custom `rx.hstack` of buttons. Radix Tabs gives `role="tablist"`/`role="tab"`/`role="tabpanel"` and arrow-key/Home/End keyboard navigation for free; a custom hstack-of-buttons would require hand-rolling all of that. |
| Tab labels (verbatim) | "Summary" \| "Forecast" \| "Data Entry" — matches D-01's names exactly, no abbreviation, no icon prefix |
| Placement | New row directly below the existing header `rx.hstack` (title + `theme_toggle()`), full page width, above the subtitle text ("Forecasts and actuals for..."). Per D-02: sticky, always visible — apply `position="sticky" top="0"` with `background=DashboardState.page_bg` so the sticky bar doesn't show content scrolling through it, and a `z_index` above chart/table content. |
| Default active tab | `"summary"` on first load (D-03) — `active_section: str = "summary"` on `DashboardState`, does NOT persist via `rx.LocalStorage` (CONTEXT.md discretion: "default to always-resets-to-Summary," Summary is the natural landing tab every session). |
| Section-to-tab mapping | "Summary" → `forecast_summary_cards()`. "Forecast" → `forecast_section()`. "Data Entry" → `historical_section()` + `data_entry_section()` rendered together as one unit (per D-01, both concern raw actuals; both mount/unmount together, never independently). |
| Rendering behavior | Conditional render (`rx.tabs.content` per tab, or an `rx.match`/`rx.cond` chain keyed on `active_section`) — only the active tab's section is in the DOM. NOT a scroll-to-anchor pattern with all sections stacked and hidden via CSS. Existing `role="region"` + `aria_label` landmarks on each section (`forecast_summary_cards`, `forecast_section`, `historical_section`, `data_entry_section`) are preserved unchanged — only the currently visible section's landmark exists in the DOM at a time, which is standard/acceptable tabbed-interface a11y behavior. |
| Scroll behavior | On tab change, scroll page to top (D-02: "behaves like a real tabbed interface"). Implement in the `on_change`/`set_active_section` event handler (e.g. `rx.scroll_to` or a small JS call), not as a separate visual/CSS concern. |
| `on_mount` | Unchanged — `on_mount=[DashboardState.load_rows, DashboardState.load_markup_pct]` stays on the single outer `rx.container` in `index()`, fires exactly once on initial page load regardless of `active_section`. Tab switching must NOT re-trigger `on_mount` or duplicate data loads. |
| State preservation | Switching tabs away from Data Entry and back must NOT reset `editing_key`, `draft_value`, `edit_error`, `pending_delete`, `draft_rows`, `import_stage`, or `_staged_import_rows` — these live on `DashboardState`, independent of `active_section`, and conditional rendering only controls DOM visibility, not component/state lifecycle, so this is satisfied by construction as long as no tab-switch handler touches these fields. |

## Accessibility Contract

| Property | Value |
|----------|-------|
| Roles | `rx.tabs.root`/`.list`/`.trigger`/`.content` (Radix Tabs primitive) render the correct `role="tablist"` on the trigger container, `role="tab"` + `aria-selected` on each trigger, and `role="tabpanel"` on the active content region automatically — no manual ARIA authoring needed, unlike a custom `rx.hstack`-of-buttons approach which would require hand-adding all of these. |
| Keyboard navigation | Radix Tabs default behavior: Left/Right arrow keys move focus between tabs and activate on focus (or on Enter/Space, depending on `activation_mode` — default `automatic`, activates on arrow-key focus, matching standard tab-widget expectation); Home/End jump to first/last tab. No custom keyboard handler required. |
| Focus indicator | Radix Themes' default focus ring on `rx.tabs.trigger` (visible outline on keyboard focus) — do not suppress it. |
| Landmark preservation | Each section's existing `role="region"` + `aria_label` (e.g. `aria_label="Data entry"`) is preserved verbatim inside its `rx.tabs.content` wrapper; do not remove or duplicate these attributes when restructuring. |
