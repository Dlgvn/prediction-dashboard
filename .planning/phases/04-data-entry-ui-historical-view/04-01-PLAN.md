    Define the three error constants with the exact UI-SPEC strings.

    `validate_numeric(raw)`: strip the input; empty -> (True, None, ""). Otherwise attempt
    `float(raw)` inside try/except ValueError -> on failure return (False, None, NUMERIC_ERROR).
    Reject with the same error when the parsed value is not `math.isfinite` or is `< 0`.
    Otherwise return (True, value, ""). Per D-01 and RESEARCH Pitfall 4 this function takes
    no column name and MUST contain no `if column ==` branch — one rule for all 16 series.

    `validate_date(raw, existing_dates, own_original_date)`: strip; parse with
    `date.fromisoformat` inside try/except (ValueError covers both unparseable strings and
    impossible calendar days) -> on failure return (False, "", DATE_INVALID_ERROR). Build the
    candidate month key as the first 7 chars of the parsed ISO string. Build the set of
    occupied month keys as the first 7 chars of each entry in `existing_dates`, EXCLUDING any
    entry equal to `own_original_date` (so a row editing its own date does not collide with
    itself). If the candidate month key is in that set, return (False, "", DATE_DUPLICATE_ERROR).
    Otherwise return (True, parsed.isoformat(), "").

    Add a module docstring naming D-01 and D-02 as the source decisions.
