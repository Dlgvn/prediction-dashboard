## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white / Radix `gray.1`) | Page background, table body background |
| Secondary (30%) | `#F1F3F5` (Radix `gray.3`) | Table header row background, alternating-row zebra stripe (optional), chart panel background |
| Accent (10%) | Radix default `blue.9` (`#3B82F6`-range, Reflex default accent) | "Add row" button, the active/selected state of the series selector dropdown, the input focus ring on an editable cell |
| Destructive | Radix `red.9` (`#E5484D`-range) | Delete control's confirm state only (second click), and validation error text/border on invalid cell input |

Accent reserved for: the "Add row" button, the series-selector dropdown's selected value, and the focus/edit-active border on a table cell being edited. Nowhere else — column headers, chart lines, and static table borders stay in the dominant/secondary neutral palette (secondary chart line color: Radix `gray.9` / `#697177`-range, not accent, since only one series shows at a time per D-04 and there's no second color to contrast against).

Source: no color decisions in CONTEXT.md or STACK.md; defaulted to Reflex's out-of-the-box Radix Themes light palette since no `rx.theme()` customization exists in `app/app/app.py`. Confirm/override at execution time if a different accent is desired.

## Interaction Contract (phase-specific, supplements standard dimensions)

These encode CONTEXT.md D-01 through D-07 as concrete, executor-actionable rules:

1. **Inline cell edit (D-05):** Click a data cell → it becomes an `rx.input` (or `rx.text_field`) pre-filled with the current value, accent-colored focus ring, auto-focused. `on_blur` and `Enter` both commit via a state event that validates (D-01/D-02) then writes through to SQLite immediately (no local-only staging) — mirrors the "DB is source of truth" pattern from PITFALLS.md. `Escape` reverts to the display value without writing.
2. **Invalid input feedback:** On validation failure, keep the cell in edit mode, add a 1px destructive-red border, and show the relevant error copy above from the Copywriting Contract in small (14px) red text directly beneath the cell. Do not write to SQLite until valid.
3. **Add row (D-06):** "Add row" button (accent, bottom of table, 8px gap above table's bottom edge) appends a blank row to the client-visible table only. Every cell in that row behaves exactly like existing cells (click-to-edit). The row is not persisted to SQLite until its Date cell holds a valid, non-duplicate month (D-02) — persisting other cells before a valid date exists is not allowed per D-06.
4. **Delete confirm (D-07):** Delete control is a trash icon button (destructive-red icon, neutral/transparent background) at the row's trailing edge. First click: relabel/recolor to solid destructive-red "Confirm delete?" state, no layout shift beyond text width. Second click (while in that state): delete immediately, no modal. Clicking elsewhere / a timeout is NOT required to revert the confirm state (keep it simple — CONTEXT.md doesn't specify a revert trigger; default to reverting on blur/click-away to avoid an accidental stray second click days later, but this is Claude's Discretion for the executor since it wasn't explicitly decided).
5. **Historical chart (D-03/D-04):** One `rx.plotly` line chart plus one `rx.select`/dropdown listing all 16 series by their display labels (reuse `_COLUMNS` labels from `app/app/app.py`, excluding "Date"). Default selection: HDAN (first headline series). Changing the selector re-renders the chart with only that series' actual values plotted against Date — never overlay multiple series, never render a grid of 16 charts.
6. **Layout order on the page:** Heading → editable data table → "Add row" button → historical chart (selector + `rx.plotly` chart) → reserved space (32px gap, per Spacing Scale) for Phase 5's forecast section. Do not add a second page/route.
