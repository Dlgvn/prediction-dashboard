    `load_all_results()`: glob `results/wf_*.json`, concatenate all records, and validate each
    against the shared record shape defined in 02-04-PLAN.md. Raise with the offending file and key
    if any record is malformed — a silently dropped family would corrupt the ranking.

    `rank_per_series(records)`: for each of hdan, ppan, diesel_usd_ton, fx_rate, sort candidates by
    `mape_mean_1_12` ascending, excluding records with null MAPE (the documented non-applicability
    records). Return the ordered list per series.

    `pick_winner(ranked, series)`: the top-ranked candidate, with these mandatory adjudication rules
    rather than a blind argmin:
    - If the top candidate is family "ml" and its record carries `"lag1_dominant"` or
      `"marginal_over_naive"` in `overfit_flags`, it does NOT win outright: promote the best
      non-ML candidate to winner and record the ML model as `runner_up`, adding the caveat
      "ML posted the lowest MAPE but its diagnostics indicate lag-1 memorisation rather than
      generalisation (D-01 overfitting caution)". This encodes D-01's explicit instruction not to
      present ML at face value.
    - If no candidate beats that series' `Naive` baseline `mape_mean_1_12`, the winner IS Naive, and
      the caveat records that no model earned its complexity for this series. This is a legitimate,
      reportable outcome, not a failure.
    - Attach `volatility_source`: "garch" plus `sigma_by_horizon` when
      `results/garch_volatility.json` marks that series `viable: true`; otherwise
      "arima_forecast_se" with `sigma_by_horizon: null` and a caveat naming the GARCH
      non-viability reason, per RESEARCH.md Pitfall 3's fallback.
    - Carry through the winner's `horizon_strategy` — D-06 explicitly allows this to differ per
      series, so never normalise the four series to one strategy.

    Write `backend_research/results/winners.json` (indent=2) exactly in the <interfaces> shape and
    print a four-row summary table: series | winning model | strategy | mean MAPE 1-12 | h=12 MAPE |
    volatility source.
  </action>
