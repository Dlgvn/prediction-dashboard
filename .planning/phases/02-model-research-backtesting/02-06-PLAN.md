  <action>
    Create `backend_research/run_ml_baseline.py`.

    `build_feature_frame(history, target)`: features are
    (a) the target's own lags 1, 2, 3; and
    (b) each predictor from `shortlist_for(target, tier="p10")` at the lag the screen selected.
    All features are `.shift()`-ed so every value was observable at the origin date — same
    anti-leakage rule as plan 02-04's exog handling. Name columns `{col}_lag{n}` so feature
    importances are self-describing in the JSON. If the shortlist is empty (possible for fx_rate),
    fall back to own-lags-only and record that in `notes`.

    Direct multi-step (`horizon_strategy: "direct"` — RESEARCH.md notes this is the natural fit for
    tree models): `fit_direct_ml(train_df, target, feature_cols, model_cls, **kwargs)` fits one
    regressor per horizon h in 1..12 against `target.shift(-h)`. Wrap the 12 fitted regressors in
    an object whose `.forecast(steps)` dispatches horizon h to model h, and hand THAT to
    `walk_forward_backtest` — all window slicing stays in the shared harness, no exceptions.

    Two model specs, deliberately regularised for the small-sample regime rather than left at
    sklearn defaults (PITFALLS.md's core warning):
    - `RandomForestRegressor(n_estimators=300, max_depth=4, min_samples_leaf=3, random_state=42)`
    - `GradientBoostingRegressor(n_estimators=200, max_depth=2, learning_rate=0.05,
      min_samples_leaf=3, random_state=42)`
    Fix `random_state=42` on both so results are reproducible across reruns; record the exact
    hyperparameters in `notes` so the report can state them.

    Harness parameters: `min_train=48, horizon=12, step=1, refit_every=3`. `refit_every=3` is the
    Pitfall 2 cost control — 12 regressors × ~100 origins × 2 model classes × 4 series is the most
    expensive run in this phase. Record the cadence in the record.

    Also record `single_holdout_mape` for D-07 comparability.

    Write records to `backend_research/results/wf_ml_baseline.json` (indent=2).
  </action>

  <action>
    Add `fit_iterative_ml(...)`: fit ONE 1-step-ahead regressor, then at forecast time predict
    step 1, shift the predicted value into the lag-1 feature slot (cascading lag-2 <- old lag-1,
    lag-3 <- old lag-2), predict step 2, and so on to step 12. Non-target predictor features hold
    their last observed (already-lagged) values across the recursion, since their future values are
    not known at the origin — state this assumption in `notes`, as it is the honest production
    scenario. Record these as `horizon_strategy: "iterative"` so D-06's comparison exists for the
    ML family too.

    Then add the D-01-mandated diagnostics to EVERY ML record (both strategies), populating the
    ML-only keys from the <interfaces> block:
    - Load `results/wf_baseline_ets.json`, find the `Naive` record for the same series, and store
      its `mape_mean_1_12` as `naive_mape_mean_1_12`. Compute
      `margin_over_naive_pct_points = naive_mape_mean_1_12 - mape_mean_1_12`. A margin at or below
      zero means the model does not beat "use last month's value."
    - Refit each model once on the full history and record the top 10
      `feature_importances_` as a name->float dict, plus `lag1_importance_share` = the importance
      assigned to the target's own `_lag1` feature.
    - Populate `overfit_flags`:
      * `"lag1_dominant"` when `lag1_importance_share > 0.5` — the model is largely reproducing a
        random walk through a lag feature, Pitfall 4's primary tell.
      * `"marginal_over_naive"` when `margin_over_naive_pct_points < 1.0`.
      * `"small_sample"` when the usable training row count after dropna is < 80.
      * `"suspiciously_strong"` when `mape_mean_1_12` is more than 30% better than the best
        statistical-family result for that series (read from `results/wf_arima_sarimax.json` and
        `results/wf_var_vecm.json` if present; skip this flag with a note if those files do not
        exist yet, since plan ordering does not guarantee them).
    - Print a stdout summary line per record: series, model, strategy, MAPE, naive margin,
      lag1 share, flags. If any record carries flags, print a closing block titled
      "OVERFITTING CAVEATS — these must appear in the research report" listing them, so plan 02-07
      cannot assemble the report without seeing them.

    Rewrite `results/wf_ml_baseline.json` with the enriched records.
  </action>
