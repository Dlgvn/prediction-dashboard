<objective>
Run the D-04/D-05 predictor screen: Granger causality across the FULL 12-predictor set against
all four targets at lags 1-3, plus Engle-Granger cointegration on levels, and emit a
machine-readable shortlist that every downstream runner uses to bound its search space.

Purpose: D-04 forbids pre-filtering predictors by intuition, but RESEARCH.md Pitfall 2 warns
that walk-forward × full predictor grid explodes computationally. The causality screen is the
principled reconciliation — test everything cheaply once, then walk-forward only what passed.
Output: `causality_screen.py`, `results/causality_screen.json`, `results/cointegration.json`.
</objective>

    `causality_matrix.py` verbatim in logic (incremental F-test: restricted model on
    `y_lag1`, unrestricted adding `x_lag`, F = ((ssr_r - ssr_u)/1)/(ssr_u/(n-k)),
    p via `scipy.stats.f.sf`) — it is already validated in this codebase, so keep it rather

    Additionally cross-check with `grangercausalitytests(data[[target, predictor]], maxlag=3)`
    for ONE pair (hdan vs baltic_an) and record both p-values in the JSON under keys
    `p` and `p_statsmodels_crosscheck` for that pair only — a cheap validation that the manual
    F-test still agrees with the library, per RESEARCH.md Pattern 3.

    `run_granger_sweep()` iterates the full cross product per D-04/D-05, with NO intuition-based
    exclusions:
    - targets: db_loader.TARGETS = hdan, ppan, diesel_usd_ton, fx_rate
    - predictors: db_loader.PREDICTORS (baltic_an, ammonia, urea_black_sea, urea_china,
      natural_gas_jkm, natural_gas_henry_hub, natural_gas_uk, natural_gas_netherlands,
      corn_us, corn_china, brent, urals) PLUS the other three targets as cross-predictors
      (so hdan<->ppan and fx<->diesel cross-relationships are covered for the VAR candidate).
      Skip only the self-pair (target == predictor).
    - lags: 1, 2, 3
    Run on percent-change data via `pct_change_frame(load_price_history())`; drop NaN pairwise
    per pair (predictor coverage differs — corn/urals start later than hdan). Record `n` per
    pair and set tier to "ns" with a `"note": "insufficient overlap"` flag when n < 24 rather
    than reporting a p-value from a degenerate fit.

    Tier assignment per Assumption A3: "p05" when p < 0.05, "p10" when 0.05 <= p < 0.10,
    else "ns". Report BOTH tiers rather than a binary cutoff so Phase 3 sees the confidence
    gradient.

    Write the result list to `backend_research/results/causality_screen.json` (indent=2) and
    print a compact per-target summary table of the significant predictors to stdout.

    `shortlist_for(target, tier="p10")` reads that JSON, keeps predictors whose best lag reached
    tier p05 or p10, dedupes to one (best-p) lag per predictor, sorts by ascending p and caps at
    6 predictors — this cap is the Pitfall 2 cost control, and the cap must be documented in the
    module docstring as a deliberate compute bound, not a modelling opinion.

    Pitfall 5 handling: do NOT special-case fx_rate. If fx_rate genuinely produces an empty
    shortlist against the expanded predictor set, `shortlist_for("fx_rate")` returns `{}` and the
    JSON must show every fx_rate pair as "ns" — that empty result is the reportable finding, and
    downstream plans will fall back to AR-only models for FX. Never lower the threshold for
    fx_rate to manufacture a predictor.
