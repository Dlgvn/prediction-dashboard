## Color

This phase introduces **exactly one new artifact**: a `DARK` token dict in `theme.py`, parallel to the existing flat `LIGHT` constants, resolved at render/compute time via `tokens(mode: str) -> dict` (per 11-RESEARCH.md Pattern 3). Same token count as light (10 tokens) — no new roles invented.

### Light (existing, reference — unchanged)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` (`PAGE_BG`) | Page background |
| Secondary (30%) | `#FFFFFF` (`SURFACE`) + `1px solid #8E9096` (`BORDER`) | Card surfaces |
| Accent (10%) | `#2563EB` (`ACCENT`) | Fan chart base line/band, horizon slider, primary buttons, active Series select |
| Destructive | `#DC2626` (`DESTRUCTIVE`) | Delete confirm/icon, validation errors, export failures |

### Dark (NEW — bespoke, hand-picked per D-03, NOT a mechanical invert)

| Token | Hex | Pairing measured | Ratio | Threshold | Result |
|-------|-----|-------------------|-------|-----------|--------|
| `PAGE_BG_DARK` | `#18181B` | (darkest layer — page canvas beneath cards) | n/a (background reference, not a text/boundary pairing) | — | — |
| `SURFACE_DARK` | `#27272A` | (card layer — one step lighter than `PAGE_BG_DARK`, mirrors the light-mode `PAGE_BG`→`SURFACE` step direction) | n/a | — | — |
| `BORDER_DARK` | `#71717A` | `BORDER_DARK` vs `SURFACE_DARK` | 3.08:1 | 3:1 (non-text boundary) | PASS (measured against candidate `#52525B` first, which measured 1.92:1 and failed — lightened within the same neutral-gray hue to `#71717A`) |
| `ACCENT_DARK` | `#60A5FA` | `ACCENT_DARK` text/icon vs `SURFACE_DARK` | 5.86:1 | 4.5:1 (normal text) | PASS |
| `ACCENT_FILL_DARK` | `rgba(96,165,250,0.15)` | (fill only, not a contrast-tested pairing — mirrors light mode's `ACCENT_FILL` derivation as the matching rgba of `ACCENT_DARK`) | n/a | — | — |
| `DESTRUCTIVE_DARK` | `#F87171` | `DESTRUCTIVE_DARK` vs `SURFACE_DARK` | 5.39:1 | 4.5:1 (normal text) | PASS |
| `NEUTRAL_LINE_DARK` | `#A1A1AA` | (chart line color — reuses `MUTED_TEXT_DARK`'s hue family; not independently re-measured, chart-line legibility is visual, not a text-contrast pairing) | n/a | — | — |
| `UP_DARK` | `#4ADE80` | `UP_DARK` vs `SURFACE_DARK` | 8.55:1 | 4.5:1 (normal text) | PASS |
| `DOWN_DARK` | `#F87171` (same value as `DESTRUCTIVE_DARK`, reused — mirrors light mode's `DOWN == DESTRUCTIVE` reuse) | `DOWN_DARK` vs `SURFACE_DARK` | 5.39:1 | 4.5:1 (normal text) | PASS |
| `MUTED_TEXT_DARK` | `#A1A1AA` | `MUTED_TEXT_DARK` vs `SURFACE_DARK` | 5.82:1 | 4.5:1 (normal text) | PASS |

All ratios computed via the WCAG 2.1 relative-luminance formula against `SURFACE_DARK` (`#27272A`), the dark-mode card/chart-figure background — the same pairing basis Phase 6 used (measuring against `SURFACE`, not `PAGE_BG`). Record these exact figures in `theme.py`'s amendment-comment block above each `DARK` dict entry, following the Task 06-03 convention verbatim (original candidate → measured ratio → final value), even where the first candidate already passed, so future changes have a documented baseline.

**Full parity requirement (THEME-04):** `tokens("dark").keys() == tokens("light").keys()` — no key present in one and absent in the other. A unit test (`test_theme_tokens.py`, per 11-RESEARCH.md's Validation Architecture) must assert this key-set equality plus the ratios above.

Accent reserved for (dark mode, identical role list to light mode — D-03 does not change *what* accent marks, only its hex): fan chart base line/band, horizon slider active track/thumb, primary CTA buttons (Export to Excel, Add row), active Series select state. Never card borders, headings, or table chrome in either mode.

## Toggle Control

| Property | Value |
|----------|-------|
| Placement | Header row, immediately adjacent to the "Prediction Dashboard" `h1` (per D-04) — inside the existing top `rx.hstack`/heading row, not a separate settings panel, not scroll-dependent |
| Visual treatment | `rx.icon_button` wrapping `rx.color_mode.icon()` (Reflex's built-in sun/moon glyph, auto-swaps per resolved mode) — matches the existing icon-button pattern already used for the delete-row control (compact size, no visible label text, `aria-label="Toggle dark mode"`) |
| Interaction | `on_click=[DashboardState.toggle_theme_mode, rx.toggle_color_mode]` — a two-item event chain per 11-RESEARCH.md Pattern 2/Open Question 1. | States | Two states only: light (sun icon shown) / dark (moon icon shown) — `allow_system=False` semantics throughout; no third "system" state is ever exposed to the user (D-02) |
| Spacing | `sm` (8px) gap between the heading text and the button, consistent with existing compact-stack spacing token usage |

## Implementation Notes (non-visual, for planner/executor continuity)

- `theme.py` must gain a `DARK` dict and a `tokens(mode: str) -> dict` lookup function alongside the existing flat `LIGHT`-equivalent constants (the current flat constants — `PAGE_BG`, `SURFACE`, etc. — become the `LIGHT` dict's values; do not delete/rename them if other code still imports the flat names without updating call sites in the same task).
- `DashboardState.theme_mode: str = rx.LocalStorage("light", name="pd_theme_mode")` is the single backend-readable source of truth for Python-computed colors (custom tokens, Plotly figures, `html`/`body` background) — kept in lockstep with Reflex's own `ColorModeContext`/`localStorage["theme"]` key via the toggle's two-item `on_click` chain. Two separate localStorage keys will exist; both must always move together (11-RESEARCH.md Pitfall re: this exact risk).
- `rx.Config(default_color_mode="light")` must be added to `rxconfig.py` (D-02) — this is the actual mechanism preventing OS-dark-mode inheritance on first load, not the previously-assumed `rx.theme(appearance="light")` pin (confirmed non-functional/stripped at render by 11-RESEARCH.md's source read).
- `html`/`body` background (THEME-01) must bind to a computed `@rx.var` reading `tokens(self.theme_mode)["PAGE_BG"]`, wired via `rx.App(style={"html, body": {"background": DashboardState.page_bg}})` — not a static hex, not a plain `assets/global.css` stylesheet (cannot reference backend state).
- Plotly figure builders (`historical_chart_figure`, `forecast_chart_figure` in `state.py`) must resolve `font.color` from `tokens(self.theme_mode)["MUTED_TEXT"]` (or `_DARK` variant) instead of the current flat `MUTED_TEXT` import — same token, mode-resolved.
