<objective>
Fix the actual OS-dark-mode-inheritance mechanism (`rx.Config(default_color_mode="light")`)
and give the Python backend a readable, localStorage-persisted theme mode var that every
server-computed color — Plotly figure colors and the html/body background token — resolves from.

Purpose: `11-RESEARCH.md` proved by direct source read that the existing
`rx.theme(appearance="light")` pin is **stripped at render** by `Theme._render()` and cannot
be what prevents OS inheritance; `default_color_mode` is unset and therefore silently
defaults to `"system"` — the exact bug class D-02 exists to prevent. It also proved that
`rx.color_mode` / `resolved_color_mode` are JS-only Vars with no Python-side value, so a
dedicated backend var is required for `@rx.var` figure builders.

Output: corrected `rxconfig.py`, `DashboardState.theme_mode` + `toggle_theme_mode()` +
mode-resolved color computed vars, mode-aware Plotly figures, and unit tests.
</objective>
