<task type="auto">
  <name>Task 1: Responsive reflow and accessibility pass</name>
  <files>app/app/app.py, app/tests/test_app_components.py</files>
  <read_first>
    - app/app/app.py (post-06-02 state — all render functions)
    - .planning/phases/06-ux-ui-redesign/06-UI-SPEC.md (Spacing Scale Exceptions note, Color table, Typography)
    - .planning/phases/06-ux-ui-redesign/06-CONTEXT.md (D-05 colorblind-safe requirement, D-07 no toggle)
    - app/app/theme.py
  </read_first>
  <action>
Responsive behavior, achieved with flex reflow rather than media queries so a single style rule covers all widths. Confirm the summary-card `rx.hstack` carries `wrap="wrap"` and that each card box uses a `flex="1 1 200px"` basis so four cards sit in one row on a wide desktop, two-up around tablet width, and one-up on a phone — with no fixed pixel width forcing overflow. Set `max_width` on the `rx.container` to a readable measure (Radix container default is acceptable; do not exceed it) and `width="100%"` with `padding_x=SPACE_MD` so content never touches the viewport edge.

Confirm horizontal overflow is contained, not page-level: the data-table box and `forecast_table()` box keep `overflow_x="auto"`; add `overflow_x="auto"` to the section wrapper only if the table box does not already own it. Set `min_width="0"` on any flex child that wraps a scrollable table, because a flex item defaults to `min-width: auto` and will otherwise push the page wider than the viewport.

Set the horizon slider to `width="100%"` with `max_width="240px"` instead of a hard `width="240px"` so it shrinks on narrow screens, and give `horizon_control()`'s `rx.hstack` `wrap="wrap"` so the label, slider, and readout stack rather than overflow.

Accessibility. Add semantic landmarks: give each major section wrapper an `aria_label` naming it ("Forecast summary", "Forecast", "Historical prices", "Data entry") and `role="region"` so a screen reader can jump between them. Give the page an `<h1>`-equivalent single top heading and ensure the section headings do not skip levels — page title, then section headings, then the sub-heading above the forecast table.

Verify non-color-dependent meaning across every place color carries information (D-05/D-11): each summary card's direction already pairs a glyph with color — confirm the glyph is inside the same text node as the percentage so it cannot be visually orphaned; the delete control pairs the red icon with the "Confirm delete?" text on arm; the export failure message and validation error must read as failures from their wording alone, not their color. Where any of these relies on color alone, add the missing text or glyph.

Give the `rx.plotly` figures an accessible fallback: set an `aria_label` on the wrapping box describing the chart ("Fan chart of forecast base value with expected range" / "Historical actual prices for the selected series") since canvas-rendered charts expose nothing useful to assistive tech.

Contrast: verify each foreground/background pairing used in the app against WCAG AA using the theme hexes — `MUTED_TEXT` on `SURFACE`, `UP` on `SURFACE`, `DOWN` on `SURFACE`, `ACCENT` as button background with white label, `BORDER` against `SURFACE` for the 3:1 non-text boundary. If any pairing falls below its threshold, darken the offending token in `theme.py` and record the change plus the measured ratio in the UI-SPEC Color table as an amendment note. Do not introduce a new accent color to fix a contrast miss — darken within the same hue.

Extend `app/tests/test_app_components.py`: add a contrast test that implements the WCAG relative-luminance formula in the test file and asserts each of the pairings above meets its threshold, reading hexes from `app.theme` so the test fails if a token regresses; assert the rendered `index()` contains an `aria_label` for each of the four section names; assert the summary-card hstack render contains `wrap`; assert the rendered page contains no fixed `width="240px"` on the slider.
  </action>
  <acceptance_criteria>
    - Contrast test passes for all declared foreground/background pairings at their WCAG AA thresholds.
    - Rendered `index()` contains all four section `aria_label` strings and both chart `aria_label` strings.
    - Summary-card container renders with flex wrap and a `200px` flex basis; no fixed pixel width on the card row.
    - `grep -c 'width="240px"' app/app/app.py` equals 0.
    - Full test suite passes.
  </acceptance_criteria>
  <verify>
    <automated>cd app && python -m pytest tests/ -q</automated>
  </verify>
  <done>Cards reflow without media queries, tables contain their own overflow, landmarks and chart labels exist, every color-carried meaning has a text or glyph equivalent, contrast is machine-verified.</done>
