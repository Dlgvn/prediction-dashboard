# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase adds exactly ONE new line to an existing component** — `_summary_card()`
in `app.py` — showing the forecasting model name and its backtested accuracy (MAPE) per
series, satisfying VIS-05. It introduces zero new design tokens, zero new colors, zero
new typography scale steps, zero new spacing values, and zero new components. Every
value below is inherited verbatim from `06-UI-SPEC.md` / `08-UI-SPEC.md` /
`app/app/theme.py` (Phase 6's locked light/dark design system, extended unchanged
through Phase 8/11/12), following the same "reuse, don't hardcode" discipline
established in prior phases. Placement, wording, and the Diesel MNT special case are
locked by `13-CONTEXT.md` D-01/D-02/D-03.

sign/direction, so the value text uses plain default body/`muted_text`-adjacent color,

Accent reserved for (unchanged from Phase 6/7/8): fan chart base line/band, horizon
slider, primary buttons (Export to Excel, Add row), active Series select state, the
"show all history" `rx.switch` checked state. This phase adds nothing to that list.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Model label (new) | "Model:" — terse, matches the existing label style ("All-time high/low:" is the longest existing label; "Model:" stays well within that width budget) |
| Model value format — standard case (HDAN, PPAN, FX rate) | `"{model_name} · {mape:.1f}% typical error"` e.g. `"SARIMAX · 13.3% typical error"`, `"Direct-OLS VAR · 23.8% typical error"`, `"Naive · 1.7% typical error"` — plain numeric-first phrasing per D-03 (no qualitative confidence tier), middle-dot (`·`) separator consistent with no other separator glyph currently used elsewhere in the card (introduces this one glyph; acceptable as plain punctuation, not a new color/icon) |
| Model value format — Diesel MNT special case (D-01) | `"Derived (Diesel USD × FX)"` — no percentage, no "typical error" suffix, since this card has no independent backtest of its own; do NOT render "N/A" or "—" for the missing percentage, simply omit it by using this full alternate sentence instead of the template above |
| No-data card state | Unchanged — "Add pricing data to see a forecast" (existing `card["no_data_text"]`, Phase 6). When a card has no forecast data at all, the new line is not rendered either (it lives inside the same `has_data == "yes"` `rx.cond` branch as the existing lines) |
| Primary CTA | "Export to Excel" / "Add row" (existing, unchanged — this phase touches no buttons) |
| Destructive confirmation | "Confirm delete?" (existing, unchanged — this phase has no destructive action) |

Source-of-truth discipline (Pitfall 4, `.planning/research/PITFALLS.md`): both
`{model_name}` and `{mape}` are read from a single new `MODEL_INFO` constant in
`forecasting.py` — never hand-typed into `state.py` or `app.py`. MAPE is formatted to
one decimal place (`{:.1f}%`) consistent with the existing `NUMBER_FORMAT`-adjacent
precision used for YoY (`+4.2%`) elsewhere on the same card.

## Interaction Contract (additive-only — no new interactive control)

This section exists because the new line is read-only computed text, not a new
control, so most of the template's Layout/Registry sections are not applicable. This
replaces the generic layout section for this phase, mirroring `08-UI-SPEC.md`'s
Interaction Contract exactly.

- **Placement:** One new `rx.hstack` row appended to the existing `rx.fragment` inside
  `_summary_card()`'s `has_data == "yes"` branch, directly below the existing "YoY"
  `rx.hstack` (app.py lines ~444-461) and above the closing of the `rx.vstack`. Card
  line order becomes: label → base number → "Expected range" → "vs. latest actual"
  direction → "All-time high/low" → "YoY" → **NEW "Model"**. This matches
  `13-CONTEXT.md` D-02 exactly (append-at-end, same pattern Phase 8 used to append
  after Phase 6's lines).
- **Data source:** The new line reads two new keys added to the SAME per-card dict
  already produced by `DashboardState.summary_cards` (`@rx.var`) — e.g.
  `card["model_label"]` (always `"Model"`) and `card["model_text"]` (the fully-formatted
  value string, computed server-side in Python so the Diesel MNT special case and the
  MAPE number formatting both happen in one place, not via multiple `rx.cond` branches
  in the component tree). One card = one dict = one `rx.foreach` item, unchanged shape
  discipline from Phase 6/8.
- **Conditional rendering:** No new `rx.cond` branch is needed beyond the existing
  `has_data == "yes"` / `"no"` split — if a card has forecast data, its model is
  necessarily known (model selection is frozen/hard-coded per series, not dynamic), so
  `model_text` is always non-empty when `has_data == "yes"`. Unlike the YoY line's D-03
  empty-string case, there is no partial/missing state for this line — every series
  (including Diesel MNT) always has a defined `model_text` value.
- **No loading state needed:** the value is a synchronous derived read from the new
  `MODEL_INFO` constant inside the existing `@rx.var`, joined with `forecast_all()`'s
  existing per-card loop — no spinner/skeleton, consistent with Phase 7/8 precedent for
  synchronous in-memory computation.
- **No new empty/error component** — the existing `card["no_data_text"]` no-data branch
  already covers the "nothing to show" case at the card level; no separate empty state
  is designed for this line since it is never partially missing when data exists.
- **`aria_label` update:** the card's existing `aria_label` (app.py lines ~474-482,
  currently ending in `+ " " + card["hilo_text"] + " " + card["yoy_text"]`) SHOULD be
  extended to include the new model text so screen-reader users get the full card
  content in one pass — e.g. append `+ " " + card["model_text"]`. This is a one-line
  change to the existing `aria_label` expression, not a new accessibility surface.
