`load_sentiment_monthly() -> pd.DataFrame`:
1. Read `RAW_CSV`; parse with `pd.to_datetime(raw["published_at"], utc=True)` (no `format=`
   argument needed — verified). Derive `local_month` as
   `(published_at + MN_OFFSET).dt.tz_localize(None).dt.to_period("M")`. Call
   `.dt.tz_localize(None)` before `.dt.to_period("M")` so pandas 2.2.3 does not emit the
   "dropping timezone information" warning.
2. Group by `local_month` and compute, per month:
   - `weighted_compound = (compound * source_weight).sum() / source_weight.sum()` — the
     formula documented in `archive/README.md`, recomputed from raw rows, NOT resampled from
     the archive's precomputed daily `weighted_compound` column (that column inherits UTC-day
     bucketing).
   - `article_count = len(group)`.
   Months with zero articles simply do not appear in a groupby result — that IS D-06's
   "drop, do not forward-fill" behavior. Do not call `.asfreq()`, `.reindex()`, `.ffill()`,
   `.bfill()`, or `.interpolate()` anywhere in this function; add a comment recording that
   D-06 forbids them.
3. Compute genuine month-unit trend columns on the monthly `weighted_compound` series:
   `sent_ema3 = weighted_compound.ewm(span=3, adjust=False).mean()`,
   `sent_ema10 = weighted_compound.ewm(span=10, adjust=False).mean()`,
   `sent_momentum = sent_ema3 - sent_ema10`. Do NOT resample the archive's day-unit
   `sent_ema3`/`sent_ema10` columns (a monthly mean of a 3-day EMA is dimensionally
   meaningless — RESEARCH.md Anti-Patterns). Add a comment saying so, because the report will
   have to explain why these values do not match a naive resample of the archive's columns.
4. Read `ML_FEATURES_CSV` with `parse_dates=["date"]`. Use the numeric `vix_regime_code`
   column, never the string `vix_regime` column (a string column makes `sm.OLS` inside
   `granger_ftest` raise a casting error — Pitfall 5). Bucket it by
   `date.dt.to_period("M")` with NO `MN_OFFSET` shift, and take the monthly `mean()`. Add a
   comment explaining the asymmetry: `ml_features.csv` is US-trading-day keyed (SPY/QQQ/DIA/VIX
   source calendar), not article-publication-timestamped, so the UTC→Mongolia article
   correction does not apply to it. Assign the result as the `vix_regime_code` column of the
   monthly frame (label-aligned; months with no ml_features coverage stay NaN — do not fill).
5. Set `df.index.name = "date"`, sort the index ascending, and apply the same defensive
   assertions `load_price_history()` uses: raise `ValueError` if the index is not a
   `pd.PeriodIndex` with `freqstr == "M"`, if it is not monotonically increasing, or if it
   has duplicates — with the same message shape (`"load_sentiment_monthly: ..."`).
6. Cast every column in `SENTIMENT_PREDICTORS` to `float64`, then raise `ValueError` if any
   `np.isinf` value is present in those columns (Pitfall 2 guard: these are bounded scores and
   ordinals, and any `inf` means a pct-change-style transform leaked in somewhere).
7. Return the frame with columns `SENTIMENT_PREDICTORS + ["article_count"]`.

`merge_lagged(y: pd.Series, x: pd.Series, lag: int) -> pd.DataFrame`:
This is the single leakage-guarded alignment point between price targets and sentiment
predictors, and the reason `LeakageError` is imported rather than a parallel guard being
written (CONTEXT.md Claude's-Discretion instruction).
1. Raise `LeakageError` if `lag < 1` — a lag of 0 aligns a sentiment month against the same
   month's price move, which is exactly the contemporaneous-leakage case the guard exists for.
   Message must name the offending lag.
2. Raise `LeakageError` if `y.index` is not a monotonically increasing monthly `PeriodIndex`,
   or if `x.index` is not a monthly `PeriodIndex` — label-based calendar alignment is the only
   thing that makes the lag semantics meaningful, and the sentiment index is gappy (20 months
   scattered across 2020-2026), so a positional shift on it would silently produce a
   multi-year "lag-1".
3. `x_on_y = x.reindex(y.index)` — project the gappy sentiment series onto the target's dense
   monthly index, leaving NaN in uncovered months. Never fill. This is what makes the
   positional `.shift()` inside the reused `granger_ftest()` equivalent to a calendar shift.
4. Build `frame = pd.DataFrame({"y": y, "y_lag1": y.shift(1), "x_lag": x_on_y.shift(lag)}).dropna()`.
   Including `y_lag1` here is deliberate: it makes `len(frame)` equal the exact `n` that
   `granger_ftest()` will compute internally, so the reported effective N is the real one
   (SENT-01 requires the *effective* monthly sample size, not a looser overlap count). Note
   this as a documented refinement over `causality_screen.run_granger_sweep()`'s precheck,
   which omits `y_lag1`.
5. Defensive post-check: recompute the expected predictor values by calendar label lookup —
   `expected = x_on_y.reindex(frame.index - lag)` — and raise `LeakageError` if
   `frame["x_lag"]` does not equal `expected` value-for-value. This assertion should never
   fire while step 3's reindex is in place; it fires if anyone later removes the reindex or
   swaps in a positional shift over the gappy index.
6. Return `frame` with columns `y`, `y_lag1`, `x_lag`.

Finally add a `__main__` diagnostic block mirroring `db_loader.py`'s: print the frame shape,
index min/max, and per-column non-null counts.

Write pandas-2.2.3-safe code per `backend_research/ENV.md` — no pandas-3.0-only behavior
assumptions. If using `groupby(...).apply(...)`, pass `include_groups=False` (available in
2.2.x) or avoid `.apply` in favor of explicit aggregation.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| checked-in `archive/*.csv` → offline research script | Static, git-tracked CSV files parsed by pandas. Not attacker-controlled at runtime; changes arrive only via reviewed commits. |
| `app/reflex.db` → research script | Read-only SQLite access, and only in Plan 02 via the unmodified `db_loader.py` (`file:...?mode=ro` URI). This plan touches no database. |

This phase is a pure offline `backend_research/` script. It is never network-facing, never
user-facing, never imported by the Reflex app process, and accepts no user input, no request
body, no query parameter, and no uploaded file. There is no authentication, authorization,
session, injection, or XSS surface to model — ASVS L1 controls for those categories are
not applicable rather than deferred.
