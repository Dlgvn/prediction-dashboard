<objective>
Load the real historical price data from `AN Data.csv`, `AN price weekly.csv` and
`Diesel Data.csv` into the `PriceRow` table, collapsing both multi-entry sources to
monthly averages and outer-merging all three on calendar month.

Purpose: This is the data that Phase 2 backtests against and Phase 3 forecasts from. If the
month collapse or the merge is wrong, every downstream model is trained on wrong numbers —
so the parsing rules are pinned by tests, not by inspection.
Output: `app/app/seed.py` with four tested public functions and a CLI entry point, plus a
populated SQLite table of 164 monthly rows spanning 2013-01 through 2026-08.

## Source 1 — `AN Data.csv` (contributes ONLY hdan, ppan)

206 data rows, 48 distinct months, 2022-08 through 2026-07. Every month has more than one
entry (per-month entry counts observed: 4 entries x 31 months, 5 x 16, 2 x 1) so the D-06b
averaging collapse applies to all of them. Date format `M/D/YYYY` (e.g. `7/10/2026`), rows
in DESCENDING date order. Header strings, verbatim (note leading/trailing spaces and the
empty 11th column from a trailing comma):
  'Date' | 'Year' | ' Month ' | ' PPAN ' | ' HDAN ' | ' Baltic AN ' | ' Ammonia '
  | ' Urea ' | ' Natural_gas ' | '  Brent  ' | ''
Numeric cells are space-padded, e.g. ` 463.56 `.

Mapping produced by `parse_an_data` — ONLY TWO COLUMNS (D-05b):
  ' PPAN ' -> ppan | ' HDAN ' -> hdan
`Year`, ` Month `, ` Baltic AN `, ` Ammonia `, ` Urea `, ` Natural_gas `, `  Brent  ` and
the unnamed trailing column are ALL discarded. D-05b retires this file as the source for
Baltic AN / Ammonia / Urea / Natural gas (superseded by the weekly file's longer history)
and for Brent (superseded by Diesel Data.csv's 2020-02 start vs. this file's 2022-08).

## Source 2 — `AN price weekly.csv` (contributes 10 columns; seeded this phase per D-07b)

711 data rows, 164 distinct months, 2013-01-11 through 2026-08-21. True weekly cadence, so
most months hold 4 or 5 entries (observed: 4 x 105 months, 5 x 57, 3 x 2) — D-06b averaging
applies. Date format `YYYY.MM.DD` (DOT separators, not slashes or dashes), column named
`Week Ending`, rows in DESCENDING date order. Headers are clean (no stray whitespace).

Mapping produced by `parse_an_weekly`:
  'Natural Gas - Japan/Korea LNG' -> natural_gas_jkm
  'Natural Gas - Henry Hub'       -> natural_gas_henry_hub
  'Natural Gas - UK'              -> natural_gas_uk
  'Natural Gas - Netherlands'     -> natural_gas_netherlands
  'Corn - US'                     -> corn_us
  'Corn - China'                  -> corn_china
  'Baltic AN'                     -> baltic_an
  'Middle East Ammonia'           -> ammonia
  'Black Sea Urea'                -> urea_black_sea
  'China Urea'                    -> urea_china

TWO-UREA-SERIES RESOLUTION (binding — do not re-decide): this file has TWO urea columns,
`Black Sea Urea` and `China Urea`. Per D-05c BOTH are kept as separate schema columns —
`Black Sea Urea` -> `urea_black_sea` and `China Urea` -> `urea_china`. Neither is dropped
and they are never collapsed into a single `urea` column. (D-05c corrects the earlier
D-05b reading under which China Urea was dropped; there is no `urea` column at all in the
schema.) Likewise `Middle East Ammonia` is the only ammonia series here and maps to
`ammonia`.

## Source 3 — `Diesel Data.csv` (contributes 4 columns; brent now sourced here per D-05b)

77 non-blank data rows, 2020-02 through 2026-06, exactly one row per month with no gaps,
ASCENDING order, PLUS ONE TRAILING ALL-BLANK ROW (`,,,,...`) that must be dropped.
Date format `YYYY-MM`. Header strings, verbatim — the four that matter:
  'Import_Volume_Price_per_ton_USD'  -> diesel_usd_ton  (e.g. ` 638.50 `)
  'URALS_Crude _Oil_(USD/BBL)'       -> urals           (NOTE the stray space after "Crude")
  'FX_rate'                          -> fx_rate         (e.g. `" 2,756.95 "` — quoted, comma thousands separator)
  'BRENT_Crude_oil_(USD/BBL)'        -> brent           (lowercase "oil"; e.g. ` 51.31 `)
Do NOT use 'Total_Import_Value_USD_Per_Ton' for diesel_usd_ton — despite its name that
column holds whole-import totals (~106,745,260), not a per-ton price.
Do NOT use 'BRENT_Crude_Oil_Price_per_Ton (USD)' or 'BRENT Crude OIL per Liter (USD)' for
brent — those are per-ton/per-liter derivations. `brent` is the USD/BBL series, matching
the units of `urals`.
