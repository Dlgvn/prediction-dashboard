## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Reflex state event | Slider `on_change` payload is client-controlled; Radix enforces min/max client-side only |
| DashboardState -> forecasting.py | Internal, already-validated data; no untrusted input crosses |
| DashboardState -> generated .xlsx bytes | Server-generated from the app's own DB; returned to the same single local user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | `set_horizon` payload | mitigate | Clamp `max(1, min(MAX_HORIZON, int(value[0])))` server-side in Task 1; forecast_all also re-validates and raises ValueError, caught in Task 2 |
| T-05-02 | Denial of Service | live-recompute on every slider tick | accept | Phase 3 D-06 backtested refits at millisecond scale for a few-hundred-row single-user dataset; RESEARCH Pitfall 3 explicitly rejects background tasks here |
| T-05-03 | Information Disclosure | .xlsx export contents | accept | Single-user local app with no auth (out of scope per REQUIREMENTS.md); export contains only the user's own price data |
| T-05-SC | Tampering | package installs | mitigate | Not applicable — this phase installs zero new packages (RESEARCH "Package Legitimacy Audit": all of reflex/pandas/openpyxl/plotly already pinned and previously audited) |
